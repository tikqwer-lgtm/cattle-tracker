# 🐄 Учёт коров — расширенный функционал

Веб-приложение для комплексного учёта коров на ферме: осеменение, отёл, аналитика, уведомления и многопользовательский режим. Работает на смартфоне, планшете и компьютере, в том числе без интернета.

**Описание функционала и работы приложения простым языком (без отсылок к коду)** — см. [ДОКУМЕНТАЦИЯ.md](ДОКУМЕНТАЦИЯ.md).

> ✅ Записи с 20+ полями  
> 🔍 Поиск и фильтрация  
> 🔔 Уведомления и напоминания  
> 📊 Аналитика (PR, CR, HDR, графики)  
> 👤 Многопользовательский режим  
> 💾 Резервное копирование  
> 💬 Чат-консультант (по работе программы, при подключённом сервере)  
> 📱 PWA (установка на устройство, офлайн)  
> ☁️ Синхронизация с сервером  
> 📥 Экспорт и импорт CSV

| Функция | Описание |

## 🛠 Установка

1. Клонируйте репозиторий или скачайте архив:
   ```bash
   git clone https://github.com/ваш-ник/cattle-tracker.git
   cd cattle-tracker
   ```

2. Соберите бандл и откройте приложение:
   ```bash
   npm run build
   ```
   Затем откройте `index.html` в браузере (двойной клик или `start index.html`). Без сборки `dist/app.js` не будет — приложение не запустится.

3. Запуск тестов: `npm test` (или `npm run test:watch` для режима слежения).

💡 Сервер не нужен — приложение работает локально. Для многопользовательского режима и мультиплатформы (десктоп, мобильные) см. [MULTIPLATFORM.md](MULTIPLATFORM.md). Запуск сервера из корня: `npm run server` (или `cd server && npm start`).

## 🌐 Синхронизация из одного источника (несколько пользователей)

Чтобы несколько пользователей работали с одной базой данных:

1. **Разверните сервер** на машине, доступной всем (VPS, облако или локальная сеть). В интернете обязателен **HTTPS** (обратный прокси с Let's Encrypt). Подробнее см. [server/README.md](server/README.md).
2. В приложении откройте **Вход** и в поле **«Адрес сервера»** укажите URL сервера (например `https://api.example.com`). Нажмите **Сохранить** — приложение перезагрузится и перейдёт в режим работы с сервером.
3. Все клиенты с одним и тем же адресом сервера видят и изменяют одни и те же данные (один источник правды).

Для локальной сети допустим `http://IP:3000`; для доступа из интернета используйте только HTTPS.

**Синхронизация записей:** источник истины — сервер. При одновременном изменении одних и тех же полей на клиенте и на сервере выигрывает последняя по времени запись (стратегия last-write-wins по полю `updated_at`). Клиент при загрузке получает поле `updatedAt` в каждой записи; при сохранении сервер перезаписывает запись и обновляет `updated_at`.

## 📦 Релизы и обновление десктопной версии (Electron)

Установленная десктопная версия может проверять обновления через GitHub Releases.

**После обновления кода (git pull):** новые функции появятся в установленной программе только после пересборки. Из корня проекта выполните `npm run electron:dist` (или в папке `electron`: `npm run dist`), затем установите новый файл из `electron/dist/`. Если вы запускаете приложение через `npm run electron` (или `cd electron && npm start`), оно уже грузится из корня — новые изменения видны после перезапуска.

**Как выпустить новую версию:**

1. В [electron/package.json](electron/package.json) поднимите `version` (например до `1.0.1`).
2. В папке `electron` выполните: `npm run dist`.
3. В репозитории на GitHub создайте **Release** с тегом `v1.0.1` (тег должен совпадать с версией с префиксом `v`).
4. Приложите к релизу установщик из `electron/dist/` (файл вида `Учёт коров Setup 1.0.1.exe`).

Пользователи увидят уведомление об обновлении при запуске или по пункту меню **Справка → Проверить обновления** (и кнопке на экране «Резервные копии»).

## 📂 Структура проекта

Исходники веб-приложения — в корне (`js/`, `css/`, `html/`, `index.html`). `index.html` собирается из partials (`html/screens/`, `scripts/assemble-html.js`, hook `prebuild`). Сборка (`npm run build`) даёт бандл `dist/app.js`. Для десктопа `electron/copy-web.js` копирует корневые исходники в `electron/`; **редактировать только корень** — устаревшие flat-файлы в `electron/js/*.js` удалены.

```
cattle-tracker/
├── index.html              # Собран из html/shell-*.html + html/screens/*
├── html/
│   ├── shell-start.html, shell-end.html
│   └── screens/            # Разметка экранов (Vite ?raw) + modals / stall-modals в index
├── manifest.json           # PWA
├── sw.js                   # Service Worker (офлайн, кэш)
├── server/                 # API (Node.js, sql.js)
│   ├── db.js               # Фасад доступа к БД
│   └── db/                 # core, users, objects, entries, protocols, farm-card, …
├── electron/               # Оболочка Electron (копия из корня при сборке)
├── capacitor.config.json   # Capacitor (Android)
├── css/
│   ├── style.css, components.css
│   ├── screens/            # Стили экранов + sync-*.css
│   └── sync.css            # Агрегатор @import sync-экранов
├── js/
│   ├── main.tsx            # ESM entry → dist/app.js
│   ├── App.tsx             # React AppShell + реестр экранов
│   ├── screens/            # React-экраны; html/screens — разметка для LegacyHost
│   ├── data/               # ESM-адаптеры сессии/хозяйства/entries
│   ├── core/               # app, menu, users — фасады + подмодули
│   ├── api/, storage/, ui/, utils/
│   └── features/           # sync/, action-batch/, stall-map/, … (фасад + подпапка)
├── scripts/
│   ├── assemble-html.js    # Сборка index.html
│   ├── split-iife-module.js  # @deprecated — не запускать новые сплиты
│   └── split-server-db.js    # Разбиение server/db.js
├── vite.config.js
```

## 📋 Меню приложения

Главный экран — кнопки по группам: **Работа с данными**, **Действия**, **Аналитика**, **Уведомления и планы**, **Настройки**. В каждой группе — подменю.

- **Работа с данными:** Добавить животное, Экспорт в Excel, Шаблон импорта, Импорт из Excel, Список всех животных, Все осеменения.
- **Действия:** Ввести осеменение, Запуск, Отел, УЗИ, Поставить на протокол.
- **Карточка хозяйства:** контакты, адреса, пункты (текст/число/дата/фото/гео → навигатор), показатели, цели со сроками, динамика, лента событий, печать A4.
- **Аналитика:** Аналитика (PR, CR, HDR, графики), Интервальный анализ.
- **Уведомления и планы:** Уведомления, Планы.
- **Настройки:** Войти / Пользователи, Резервные копии, Протоколы синхронизации, **Чат-консультант**.
- **Чат-консультант** — ответы на вопросы по работе программы (требуется адрес сервера и настройка DeepSeek на сервере). В десктопной версии также: **Справка → Чат-консультант** и вызов по **ПКМ** (правый клик → «Вызвать консультанта»).
- На экране меню — переключатель **Объект** (база), статистика стада, блок уведомлений.
- **Очистить повреждённые данные** / **Удалить повреждённые записи** — в разделе данных; исправление или удаление битых записей.

## 🔍 Поиск и фильтрация

На экране **Просмотр описи**:

- **Поиск** — по номеру, кличке, статусу, быку, коду, примечанию, осеменатору, протоколу.
- **Фильтры** — по статусу (несколько), лактации, периоду дат осеменения, признаку «синхронизировано».
- Кнопка **Сбросить** — очистка поиска и фильтров.
- Настройки фильтров сохраняются в браузере.

---

## 🔔 Уведомления

- Проверка при загрузке и по таймеру (раз в минуту).
- Типы: предстоящий отёл (за 7, 3, 1 день), рекомендация осеменения (60+ дней после отёла), запуск в сухостой, напоминание о несинхронизированных записях.
- В разделе **Уведомления** — история, кнопки «Проверить сейчас» и «Очистить историю».
- При разрешении — браузерные (push) уведомления.

---

## 📊 Аналитика

- **PR** — доля стельности (упрощённый расчёт).
- **CR** — доля оплодотворения по попыткам.
- **HDR** — доля выявленной охоты.
- **Сервис-период** — средние дни от отёла до осеменения.
- Период: месяц, квартал или год.
- Графики: столбцы показателей и круговая диаграмма по статусам (Chart.js).

---

## 👤 Пользователи

- **Без авторизации** — работа как раньше, все записи доступны.
- **Войти** — по логину и паролю (хранятся в `localStorage`).
- **Регистрация** — логин, пароль, роль: Оператор, Администратор или Только просмотр.
- Администратор видит все записи; оператор и просмотр — только свои (где указан его `userId`). Новые записи при входе помечаются текущим пользователем.

---

## 💾 Резервные копии

- **Создать резервную копию** — снимок текущих записей в `localStorage`.
- **Экспорт в файл** — скачать JSON с данными.
- **Импорт из файла** — загрузить JSON и заменить текущие записи (после подтверждения).
- В списке копий — **Восстановить** (подставить выбранную копию) или **Удалить**.
- Хранится до 10 копий в браузере; старые автоматически удаляются.

---

## ☁️ Синхронизация с сервером

Синхронизация данных выполняется через сервер API (см. раздел «Синхронизация из одного источника» выше). Адрес сервера пользователь вводит в **Настройки → Войти**. Для кнопки «Подключиться к серверу» на экране Синхронизация можно задать адрес по умолчанию в `js/config.js` (переменная `CATTLE_TRACKER_DEFAULT_SERVER_URL`).

---

## 📦 Экспорт и импорт CSV

- **Экспорт** — все записи в CSV с разделителем `;`, BOM для корректной кириллицы в Excel.
- **Импорт** — по номеру коровы: нет в базе — добавляется, есть — обновляются поля из файла. Поддерживаются кавычки и разделители `;` или `,`.

## 📱 PWA

- Подключены `manifest.json` и Service Worker (`sw.js`).
- В браузере можно установить приложение на главный экран и использовать офлайн (кэш страницы и скриптов).

## 🎤 Голосовой ввод (если подключён)

Скажите **«Гена»**, затем по очереди: номер коровы, кличка, дата, бык, попытка, статус и т.д., в конце — **«Запиши»**. Поддерживается распознавание дат и подстановка в форму.

## 💬 Чат-консультант

При подключённом сервере (указан адрес в Настройках) доступен чат-консультант — ответы на вопросы по работе программы. Контекст нейросети (DeepSeek) формируется из документации (README, инструкции). Открытие: **Настройки → Чат-консультант**; в десктопной версии также **Справка → Чат-консультант** и правый клик по экрану → «Вызвать консультанта». На сервере требуется переменная окружения `DEEPSEEK_API_KEY` (см. [server/README.md](server/README.md)).
