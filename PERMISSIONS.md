# Матрица прав (роли приложения)

Коды ролей в БД / JWT: `admin` | `inseminator` | `service`.  
Подписи в UI: **Админ** / **Осеменатор** / **Сервис-специалист**.

Источник в коде клиента: `CAPABILITY_MATRIX` в `js/core/users/part-1.js` (и зеркало в `electron/js/`).  
Серверные проверки: `requireRole` / `requireObjectAccess` в `server/auth.js` и маршрутах `server/routes/`.

Админ на главном меню может включить **предпросмотр** UI-роли (`sessionStorage.cattleTracker_previewRole`). JWT не меняется. В предпросмотре клиент блокирует записи.

При изменении прав обновляйте **этот файл** вместе с матрицей и API.

Администратор может переопределить функции ролей **осеменатор** и **сервис-специалист** на вкладке «Права» в администрировании. Значения по умолчанию — в таблице ниже; сохранённые переключатели хранятся на сервере и применяются всем пользователям этой роли. Права администратора не переключаются.

## Capability (клиент)

| Capability | Описание | admin | inseminator | service |
|---|---|---|---|---|
| `cards` | Просмотр карточек животных | да | да | да |
| `eventsInput` | Полный ввод действий стада (отел, запуск, аборт, добавление) | да | да | нет |
| `serviceWorksInput` | Ввод работ специалиста: осеменение, УЗИ, постановка на протокол | да | да | да |
| `workLists` | Списки работ | да | да | да (просмотр) |
| `stallMap` | Карта стойл | да | да | да (просмотр) |
| `inventory` | Инвентаризация / изменение привязок | да | да | нет |
| `notifications` | Центр уведомлений (временно скрыт в UI) | да | да | да |
| `analytics` | Аналитика | да | нет | нет |
| `farmCardSettings` | Правка карточки хозяйства / настроек фермы | да | нет | нет |
| `farmCardEventsWrite` | Запись ленты событий карточки хозяйства | да | нет | да |
| `farmCardView` | Просмотр карточки хозяйства | да | да | да |
| `multiBase` | Переключатель среди **доступных** объектов | да | да | да |
| `adminUsersRoles` | Администрирование пользователей, назначение объектов | да | нет | нет |
| `adminReleaseControls` | APK / служебные админ-контроли | да | нет | нет |
| `createDeleteObjects` | Создание и удаление объектов (баз) | да | нет | нет |

## Доступ к объектам (сервер)

| Действие | admin | inseminator | service |
|---|---|---|---|
| Список объектов `GET /api/objects` | все объекты | только назначенные | только назначенные |
| Чтение данных объекта (entries, protocols, farm-card…) | любой объект | назначенные | назначенные |
| Создание / удаление entries | да | да (назначенные) | создание вместе с работой (осеменение / УЗИ / протокол); удаление — нет |
| PUT entries (осеменение / УЗИ / протокол) | да | да (назначенные) | да (только эти поля) |
| Запись protocols / stall-layout | да | да (назначенные) | нет |
| PUT farm-card (вся карточка) | да | нет | нет |
| PUT farm-card (только events) | да | нет | да |
| Создание / импорт / переименование / удаление объекта | да | нет | нет |
| Назначение пользователей к объектам | да | нет | нет |

Админ видит все объекты **без** строк в `user_objects`. Остальные — только через `user_objects`.
