## Правила валидации (обновлённые тексты и сценарии)

### Осеменение

- Стельным (статус содержит «Стельная») осеменение вносить нельзя — модалка **Продолжить / Отмена** с пояснением (как в базовом плане).

### Запуск (сухостой)

- Условие предупреждения: не стельная **или** дни стельности на дату запуска вне интервала **[210, 270]** (включительно).
- **Текст ошибки (единый шаблон):** «Не является стельной или не соответствует норме по дням стельности» + **указать фактическое количество дней** (если дней нет — явно «дни не определены» или аналог).
- Кнопки: **Отмена** / **Продолжить**.

### УЗИ

- Разрешено, если статус **«Осеменена*» или «Стельная»** (ИЛИ), и есть осеменение до даты УЗИ (как договорено).
- **Текст ошибки:** «Не является осемененной или стельной для подтверждения стельности» + в скобках/с новой строки **«Статус — …; дни стельности — …»** (дни на дату УЗИ по той же логике, что для запуска, либо «—» если не считается).
- Кнопки: **Отмена** / **Продолжить**.

### Отёл

- **Вариант 1 (не стельная):** текст «Животное не стельное» — **Отмена** / **Продолжить**.
- **Вариант 2 (стельная, но срок стельности не соответствует норме для отёла — не более 240 дней по правилу «> 240»):** текст «Срок стельности не соответствует норме, занести как аборт?»
- Для варианта 2 — **три кнопки:** **Отмена**, **Продолжить**, **Аборт**.
  - **Продолжить** — **только отёл**: выполняется обычный `applyCalvingToEntry` (полноценный отёл), несмотря на предупреждение о сроке.
  - **Аборт** — сценарий действия «Аборт» (`applyAbortToEntry`), без полноценного отёла по правилам варианта 1.

### Протокол (дополнения)

1. **Нельзя одновременно быть на двух протоколах** — при попытке назначить второй активный протокол без снятия первого — предупреждение.
2. **Нельзя ставить на протокол, если корова уже на протоколе** (есть непустые `protocol.name` / актуальная постановка — уточнить критерий «на протоколе» в коде: наличие имени и даты начала).
3. Модалка: показать **название текущего протокола**; кроме **Отмена** и **Продолжить** (или вместо «Продолжить» — уточнить UX) добавить действие **«Отменить предыдущий протокол»**: снимается старый протокол (очистка `protocol` или явная запись в историю «снятие» — по согласованию с историей событий), **назначается новый**.

Стельным на протокол не ставим — как в базовом плане.

### Дубли события в одну дату

- Как в базовом плане: осеменение, УЗИ, отёл, запуск, протокол (по критериям дубля) — предупреждение **Отмена** / **Продолжить**.

## Новое действие меню: «Аборт»

- Назначение: животные, **сбросившие телёнка раньше срока** (аборт / мертворождение и т.п. — формулировка для пользователя в UI).
- **Обычный случай (не после запуска / не «Сухостой»):** при сохранении действия животное получает статус **«Холостая»**, **данные текущей лактации сохраняются** (не сбрасывать лактацию/поля как при полном отёле без уточнения — в реализации зафиксировать список полей).
- **Исключение — животное в статусе «Сухостой»** (уже был запуск): не оставляем просто «Холостая» с той же лактацией; открывается **новая лактация**, статус выставляется **«Отёл»** по **тем же правилам, что при вводе отёла** (как при нормальном отёле после сухостоя — переиспользовать `applyCalvingToEntry` / `archiveCurrentLactation` или эквивалент с датой события аборта как «дата отёла» для перевода лактации — **уточнить в реализации одним местом**, чтобы не разъехалась история).

Точки UI: пункт в [`js/core/menu.js`](e:/VScode/cattle-tracker/js/core/menu.js) (группа «Действия»), экран пакетного ввода по аналогии с отёлом/УЗИ или одиночная форма — в плане заложить **пакет + при необходимости карточка**.

Запись в **историю действий** (`pushActionHistory`) для события типа «Аборт» с датой и пояснением.
