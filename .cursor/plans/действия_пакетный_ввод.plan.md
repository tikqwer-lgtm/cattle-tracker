# Пакетный режим экранов «Действия» (актуализировано)

## Общий каркас (без изменений)

Для пунктов меню «Действия»: общие поля сверху, специалист по умолчанию из `getCurrentUser().username` (где уместно), строка ввода номера с автодополнением, таблица черновика, клик по строке — правка, **«Сохранить»** применяет все строки к карточкам.

Кодовая база: [js/ui/cow-operations.js](js/ui/cow-operations.js), [js/features/insemination.js](js/features/insemination.js), разметка экранов в [index.html](index.html).

---

## Ввод осеменения — после выбора номера

- После выбора коровы в черновике (или в модалке шага добавления) показывается поле **«Попытка»**.
- Значение по умолчанию: **текущая попытка коровы + 1** (логика как при добавлении новой попытки в карточке: из `attemptNumber` / последней записи `inseminationHistory`).
- Пользователь может изменить число вручную перед добавлением строки в таблицу или в модалке редактирования строки.
- Остальные общие поля осеменения (дата, бык, осеменитель) — как в текущей форме; применение — через вынос `applyInseminationToEntry`.

---

## Дата отёла — после выбора номера

1. **Маленькое окно** (модалка) с полями:
   - **Номер теленка** (необязательно: если пусто — телёнок в базу не создаётся, только отёл матери по общим правилам).
   - **Вес**
   - **Пол** (для определения статуса новорождённого)

2. **При внесении номера теленка** (и подтверждении):
   - В `entries` добавляется **новая запись** (отдельное животное):
     - **Номер животного** = введённый номер теленка
     - **Дата рождения** = дата отёла (общая дата отёла с экрана или со строки)
     - **Статус** = **«Бык»** или **«Телка»** в зависимости от пола при рождении
     - Новое поле **«Родитель М»** — номер матери (корова, для которой вводится отёл)
     - Новое поле **«Родитель О»** — номер **быка последнего осеменения матери** (из `inseminationHistory` / поля быка на момент отёла; уточнить единый источник — последняя запись до даты отёла)

3. **Вес** — сохранять в карточке телёнка (новое поле, например `birthWeight` или `calfBirthWeight`), если такого поля ещё нет в схеме [js/storage/storage-entries.js](js/storage/storage-entries.js) / `getDefaultCowEntry`.

4. **Отображение в списке черновика** на экране отёла:
   - Строка **мать** (ввод отёла)
   - **Под ней** вложенно/группой — строка **телёнок** (если номер теленка был введён): номер, дата рождения, статус, родители (кратко).

5. **Сохранение пакета:**
   - Сначала/вместе с отёлом матери: обновить мать (`saveCalvingEntry` / `applyCalvingToEntry`).
   - Создать запись телёнка с полной инициализацией полей + `saveLocally` / `createEntryViaApi` для новой карточки.
   - В списке «все животные» позже можно группировать мать–телёнок (отдельная задача UI); минимум — корректные поля в данных.

6. **Миграция данных:** для старых записей без «Родитель М/О» — поля пустые; не ломать импорт/экспорт (добавить ключи в список полей при необходимости).

## Остальные экраны (кратко)

- **УЗИ** — модалка результата Стельная / Не стельная / Отмена; общие дата и специалист; см. предыдущее описание плана.
- **Запуск**, **На протокол** — пакет без доп. модалок (кроме правки строки).

## Порядок внедрения (рекомендуемый)

1. Схема записи: поля `parentMother`, `parentFather` (или русские ключи в UI + англ. в JSON), `birthWeight`; обновить `getDefaultCowEntry`, очистку при новой лактации матери **не** трогать для телёнка (телёнок — отдельная запись).
2. УЗИ пакетный UI + `applyUziToEntry`.
3. Осеменение: пакет + попытка +1.
4. Отёл: модалка телёнка + создание дочерней записи + визуал «мать + телёнок» в черновике.
5. Запуск, протокол; синхронизация electron.

## Открытые уточнения (при реализации)

- Единицы веса (кг) и обязательность поля «Вес».
- Если номер теленка уже существует в базе — запрет дубликата или слияние.
- Для матери без последнего осеменения: «Родитель О» — пусто или «—».
