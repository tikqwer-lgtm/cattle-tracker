# План выполнения (переписан под запуск)

## Цель

Разнести [js/features/action-batch.js](js/features/action-batch.js) на модули **без изменения логики**: те же шесть функций на `window` (`initActionBatchUziScreen`, `Dry`, `Protocol`, `Insemination`, `Calving`, `Abort`), те же DOM id, цепочки Promise, вызовы `ActionInputGuards`, `runSequentialUpdates` и т.д.

## Подход

1. **`action-batch-core.js`** — общие хелперы и выставление **`window.__actionBatch`** (внутренний API, не для HTML).
2. **Шесть файлов экранов** — каждый IIFE: `var AB = window.__actionBatch`, локальные `*Draft` и функции как сейчас, в конце присвоение своего `window.initActionBatch…`.
3. **`action-batch.js` (фасад)** — только `import` core + шести файлов и `export {}`.
4. **[js/main.tsx](js/main.tsx)** — по-прежнему одна строка `import './features/action-batch.js'` (порядок относительно соседей не меняется).

## Инварианты

- Не переименовывать публичные `window.initActionBatch*`.
- Не менять порядок загрузки относительно `insemination.js` / `view-cow.js` (фасад остаётся на месте).
- Правки только в `js/` (Electron подтянет `copy-web.js`).

## После кода

- Поднять patch в корневом `package.json`.
- `npm test`, затем `npm run installer`.

## Отложено (не в этом запуске)

- Сплит `sync.js`, аудит дублей в корне `js/`, dynamic import — по необходимости отдельным проходом.
