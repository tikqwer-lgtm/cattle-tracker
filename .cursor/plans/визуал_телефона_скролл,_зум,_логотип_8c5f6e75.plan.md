# Визуальное оформление приложения на телефоне

## Текущее состояние

- **Прокрутка:** основной контент и списки используют `overflow: auto` или `overflow-y: auto`; в [css/responsive.css](css/responsive.css) на экранах ≤600px у [.view-entries-wrapper](css/responsive.css) задано `overflow-x: auto` и таблица имеет `min-width: 600px`, из‑за чего возможна горизонтальная прокрутка и за пределами списков.
- **Логотип:** в меню и печатной шапке используется [icons/icon.svg](icons/icon.svg); в [index.html](index.html) блок `.menu-branding` (стр. 88–90) и `#print-header` (стр. 25–31) ссылаются на него. Нужно использовать логотип с приложенной картинки (корова + текст «МОЛОЧНАЯ КОМПАНИЯ ГЕНЕТИКА»).
- **Масштабирование списков:** жестов зума в списках нет; логика списков — [js/features/view-list.js](js/features/view-list.js) (виртуальный список описи), [js/features/lists.js](js/features/lists.js) (таблицы УЗИ/осеменение), плюс `#allInseminationsList` в index.html.

## 1. Только вертикальное движение окна (без горизонтальной прокрутки, кроме списков)

**Цель:** на телефоне не должно быть горизонтальной прокрутки основного экрана; в списках горизонтальная прокрутка допустима только при широкой таблице (много столбцов).

**Подход:**

- В [css/responsive.css](css/responsive.css) (или в отдельном блоке для мобильных, например `@media (max-width: 768px)`):
  - Задать для `html` и `body`: `overflow-x: hidden` (и при необходимости `overflow-y: auto`), чтобы убрать горизонтальный скролл страницы.
  - Для основных контейнеров экранов (например, `.screen`, контейнеры с контентом в [css/base.css](css/base.css) / [css/layout.css](css/layout.css)): `overflow-x: hidden; overflow-y: auto`, чтобы скролл был только по вертикали.
- Исключения (горизонтальная прокрутка только там, где нужна):
  - [.view-entries-wrapper](css/components-tables.css) (описи, виртуальный список) и [.view-virtual-body](css/components-tables.css) — оставить возможность горизонтальной прокрутки при широкой сетке столбцов (`overflow-x: auto` только для этих обёрток или только внутри них).
  - [.list-table-wrap](css/style.css) (таблицы УЗИ/осеменение в [js/features/lists.js](js/features/lists.js)) — уже имеет `overflow-x: auto`; оставить как есть.
- Опционально: для мобильных добавить `touch-action: pan-y` на `body`, чтобы не провоцировать горизонтальный свайп (для областей со списками можно не переопределять, чтобы не мешать жесту зума).

В [css/responsive.css](css/responsive.css) уже есть медиа `max-width: 600px` с правилами для `.view-entries-wrapper`; нужно не убирать там `overflow-x: auto` у обёрток списков, а добавить выше по иерархии (body, .screen) ограничение по горизонтали.

## 2. Масштабирование списков пальцами (pinch-to-zoom)

**Цель:** в списках (описи, УЗИ, осеменение, все осеменения) возможность масштабировать контент жестом щипка.

**Подход:**

- Вынести общую логику в утилиту, например [js/utils/pinch-zoom.js](js/utils/pinch-zoom.js) (или в существующий модуль утилит):
  - Принимать контейнер списка (DOM-элемент) и опционально внутренний элемент, к которому применять `transform: scale(...)` (если не передан — масштабировать сам контейнер).
  - Обрабатывать `touchstart` / `touchmove` / `touchend`: при двух пальцах считать изменение расстояния между ними и обновлять коэффициент масштаба (например, в пределах 0.7–1.5 или 0.8–1.5).
  - Применять `transform: scale(zoom)` с подходящим `transform-origin` (например, центр между двумя пальцами или центр контейнера).
  - Не мешать обычной вертикальной/горизонтальной прокрутке (однопальцевые касания не трогать).
- Подключить эту логику к:
  - **Описи стада:** в [js/features/view-list.js](js/features/view-list.js) после создания разметки виртуального списка (`#viewVirtualBody` или обёртка вокруг него) — инициализировать pinch-zoom для контейнера списка (масштабировать внутреннюю область с заголовком и строками).
  - **Списки УЗИ/осеменение:** в [js/features/lists.js](js/features/lists.js) после `wrap.innerHTML = ...` для `#uzi-list-table-wrap` и `#insem-list-table-wrap` — инициализировать pinch-zoom для соответствующего wrap.
  - **Все осеменения:** аналогично для контейнера `#allInseminationsList` (если он рендерится как список/таблица; при необходимости определить точное место в коде, где заполняется этот блок).
- Учесть виртуализацию в view-list: масштабировать стоит обёртку, содержащую и шапку, и `.view-virtual-body`, чтобы зум применялся ко всему списку, а не только к видимым строкам.

## 3. Логотип с картинки

**Цель:** использовать в приложении логотип с приложенной картинки (корова + «МОЛОЧНАЯ КОМПАНИЯ ГЕНЕТИКА»).

**Шаги:**

- **Ассет:** разместить изображение логотипа в проекте так, чтобы оно попадало в сборку. Сейчас в [vite.config.js](vite.config.js) в `dist` копируется папка [icons](icons/). Имеет смысл сохранить логотип как `icons/logo-genetika.png` (или скопировать из приложенного файла, если он лежит в `assets/` или в другом месте в репозитории).
- **Меню:** в [index.html](index.html) в блоке `.menu-branding` (стр. 88–90) заменить `icons/icon.svg` на путь к новому логотипу (например `icons/logo-genetika.png`). При необходимости добавить класс для полноформатного логотипа (без круглой обрезки).
- **Печать:** в `#print-header` (стр. 25–31) заменить `icons/icon.svg` на тот же логотип.
- **Стили:** в [css/layout.css](css/layout.css) у [.menu-branding-logo](css/layout.css) сейчас задано `border-radius: 50%`. Для прямоугольного логотипа с текстом убрать скругление (или задать его только для старого icon.svg через отдельный класс). При необходимости подправить размеры (width/height), чтобы логотип хорошо смотрелся в шапке меню и в печатной шапке.

После сборки `dist` будет содержать `icons/logo-genetika.png`, и Capacitor скопирует его в Android (webDir: `dist`), так что на телефоне будет отображаться новый логотип.

## Порядок внедрения

1. CSS: вертикальная прокрутка и запрет горизонтальной вне списков (responsive.css + при необходимости base/layout).
2. Логотип: добавить файл в `icons/`, обновить index.html и layout.css.
3. Утилита pinch-zoom и подключение к view-list, lists и при необходимости к экрану «все осеменения».

В конце — сборка (`npm run build`) и при необходимости `npx cap sync` для проверки на устройстве.
