# План исправлений по сводке отчётов

## 1. Список на осеменение и список задач

**Проблемы:** печать не работает; экспорт в Excel не работает; нужно убрать печать с мобильной версии.

**Причины:**

- Печать и Excel используют глобальный `XLSX` из скрипта в [index.html](index.html) (строка 746). В мобильном WebView CDN может не загружаться или порядок загрузки бандла и скриптов может быть другим — в итоге `XLSX` может быть `undefined`.
- В [js/features/lists.js](js/features/lists.js) экспорт вызывает `exportListToExcel` (строки 521–547), при отсутствии XLSX показывается тост «Библиотека Excel не загружена».
- Список задач в [js/features/notifications.js](js/features/notifications.js) (строки 479–484) вызывает `global.exportListToExcel`; `global.exportListToExcel` выставляется в [js/features/lists.js](js/features/lists.js) (строка 693).

**Действия:**

- **Мобильная версия:** ввести определение «мобильный» (например `matchMedia('(max-width: 768px)')` или проверка `navigator.userAgent`/флага) и в [js/features/lists.js](js/features/lists.js) при рендере списка на осеменение не показывать кнопку «Печать» (скрывать `#insemListPrint` или не добавлять её в разметку при `isMobile`). Аналогично в [js/features/notifications.js](js/features/notifications.js) скрыть кнопку «Печать» в блоке `.tasks-list-actions` на мобильных.
- **Excel:** чтобы экспорт работал и на мобильных, подключить XLSX в бандл (npm-пакет `xlsx`), а не полагаться на CDN: в [js/main.tsx](js/main.tsx) или в модуле экспорта подключать/инициализировать XLSX и передавать его в логику экспорта (или выставлять `window.XLSX` после импорта). В [js/features/lists.js](js/features/lists.js) оставить проверку `typeof XLSX === 'undefined'` и сообщение пользователю, если библиотека всё ещё не доступна.
- При необходимости для мобильных добавить запасной вариант скачивания (например, задержка перед `URL.revokeObjectURL` или использование Web Share API для файла), как в пункте про резервную копию.

## 2. Интервальный анализ — «Нет данных»

**Проблема:** на экране `#interval-analysis` не отображаются данные.

**Причина:** в [js/features/analytics.js](js/features/analytics.js) в `getIntervalAnalysisData` (строка 314) используется глобальная переменная `entries`, а для списка осеменений — `getInseminationListForEntry`. В ESM-бандле глобальные `entries` и `getInseminationListForEntry` могут быть недоступны в области видимости модуля (они заданы в `storage-objects.js` и `view-cow.js` и не экспортируются в модуль analytics).

**Действия:**

- В `getIntervalAnalysisData` заменить обращение к глобалам на явное использование `window`:
  - `var list = (typeof window !== 'undefined' && window.entries && Array.isArray(window.entries)) ? window.entries : [];`
  - `var getList = (typeof window.getInseminationListForEntry === 'function') ? window.getInseminationListForEntry : function () { return []; };`
- В [js/features/view-cow.js](js/features/view-cow.js) в блоке, где вешаются методы на `window` (около строк 585–589), добавить: `window.getInseminationListForEntry = getInseminationListForEntry;`

## 4. Экран просмотра (#view)

### 4.1 Кнопка «Вверх» отсутствует

**Где:** кнопка есть в разметке [index.html](index.html) / [electron/index.html](electron/index.html): `#viewScrollToTopBtn` с текстом «↑ Вверх». Логика в [js/features/view-list.js](js/features/view-list.js): `_setupScrollToTopForContainer` привязывает кнопку к контейнеру прокрутки (`#viewEntriesList` или при виртуализации — `#viewVirtualBody`), показывает при `scrollTop > 200`.

**Действия:** проверить, что на мобильных кнопка не скрыта CSS (например, не перекрыта или не обрезана). В [css/components-tables.css](css/components-tables.css) у `.scroll-to-top-btn` (строки 106–118) при необходимости добавить медиа-запрос для маленьких экранов (например, `bottom: 16px; right: 16px;` и достаточный `z-index`), чтобы кнопка была видна и кликабельна. Убедиться, что при первом рендере списка (и при переключении виртуальный/обычный режим) вызывается `_setupScrollToTopForContainer` с актуальным контейнером прокрутки.

### 4.2 Режим редактора на телефоне — поля «разъезжаются»

**Где:** кнопка «Режим редактора» — `#viewEditorModeBtn` в разметке; логика в [js/features/view-list.js](js/features/view-list.js) (`initViewEditorModeButton`). Стили редактируемых ячеек — [css/components-tables.css](css/components-tables.css) (например, `#viewEditorModeBtn.active`, `.view-list-editor-mode`).

**Действия:** на мобильных скрыть режим редактора: при определении мобильного (то же, что в п. 1) скрывать кнопку `#viewEditorModeBtn` (или не рендерить её) и не включать режим редактора при открытии экрана на мобильном.

### 4.3 Названия столбцов — выровнять по центру и по середине

**Где:** заголовки таблицы в [js/features/view-list.js](js/features/view-list.js) (обычная таблица — `<th>`, виртуальный список — `.view-virtual-head-cell`). Стили — [css/components-tables.css](css/components-tables.css): `.entries-table th` (строки 12–25), виртуальная шапка — классы для `.view-virtual-head`.

**Действия:** для заголовков таблицы просмотра задать выравнивание по центру по горизонтали и по вертикали по середине: в CSS для `.entries-table th` и для ячеек виртуальной шапки (например, `.view-virtual-head-cell`) добавить `text-align: center; vertical-align: middle;` (для грида при необходимости выравнивание через `align-items: center; justify-items: center;` или аналог).

### 4.4 Шаблон не сохраняется — saveFieldTemplates is not defined

**Проблема:** при сохранении шаблона полей в консоли: `ReferenceError: saveFieldTemplates is not defined` (в бандле app.js).

**Причина:** `saveFieldTemplates` определена в [js/features/view-list-fields.js](js/features/view-list-fields.js) (строка 65), но не экспортируется и не вешается на `window`. [js/features/view-list.js](js/features/view-list.js) вызывает `saveFieldTemplates(list)` (строки 349 и 373), но в ESM-бандле у каждого модуля свой scope, поэтому в view-list эта функция недоступна.

**Действия:** в [js/features/view-list-fields.js](js/features/view-list-fields.js) в блоке, где на `window` выставляются другие методы (строки 76–84), добавить: `window.saveFieldTemplates = saveFieldTemplates;`

## 5. Кнопка «Отправить на сервер» для пользователей без базы синхронизации

**Задача:** дать возможность отправить данные на сервер тем, у кого нет настроенной базы для синхронизации (например, только локальная работа).

**Где:** экран синхронизации [index.html](index.html) — блок `#sync-connect-block` (когда сервер не подключён) и [js/features/sync.js](js/features/sync.js): `connectToServer`, `uploadCurrentBaseToServer` (строка 499), `window.uploadCurrentBaseToServer` (строка 716).

**Действия:** в блоке `#sync-connect-block` (или рядом с «Подключиться к серверу») добавить кнопку «Отправить на сервер». По нажатию: если сервер ещё не подключён — вызвать сценарий подключения (например, открыть настройки/модалку ввода URL и логина, затем после успешного подключения выполнить загрузку текущей базы); если уже подключён — вызвать `uploadCurrentBaseToServer()`. Реализовать в [js/features/sync.js](js/features/sync.js) (например, обёртка `sendToServer()` или расширение `connectToServer` с опцией «подключить и загрузить текущую базу») и повесить вызов на новую кнопку в разметке или в коде, который рендерит блок подключения.

## 6. Резервная копия не работает на телефоне

**Проблема:** создание резервной копии не срабатывает на мобильном.

**Где:** [js/features/backup.js](js/features/backup.js), функция `exportBackupToFile()` (строки 88–102): формируется JSON, Blob, `URL.createObjectURL`, создаётся `<a download="...">`, вызывается `a.click()`, затем сразу `URL.revokeObjectURL(url)`.

**Причины на мобильных:** программный `a.click()` часто блокируется или не запускает скачивание в iOS Safari и части Android-браузеров; атрибут `download` не всегда поддерживается; ранний `revokeObjectURL` может отзывать URL до начала загрузки.

**Действия:**

- Отложить `URL.revokeObjectURL(url)` (например, `setTimeout(..., 1000)` или отзывать после события, если есть возможность подписаться на завершение «скачивания»).
- Добавить запасной вариант для мобильных: при наличии `navigator.share` и типа `application/json` (или сконвертировать в File) предлагать «Поделиться» через Web Share API; при отсутствии — показывать сообщение «Скопируйте данные» и выводить JSON в модалке/текстовом поле для ручного копирования (или кнопка «Скопировать в буфер»).
