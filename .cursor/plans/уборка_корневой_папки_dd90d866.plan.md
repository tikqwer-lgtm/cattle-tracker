# Уборка главной папки проекта

## Текущее состояние корня

В корне лежат: конфиги (`package.json`, `vite.config.js`, `capacitor.config.json`, `tsconfig.json`, `eslint.config.js`, `playwright.config.js`, `vitest.config.js`), точка входа веб-приложения (`index.html`, `manifest.json`, `sw.js`), документация (README.md, MULTIPLATFORM.md, RELEASE_CHECKLIST.md и др.), скрипты запуска (`.bat`/`.cmd`), папки `css/`, `js/`, `electron/`, `server/`, `android/`, `ios/`, `dist/`, `e2e/`, `tests/`, `scripts/`, `lib/`, `icons/`, а также `.cursor/`, `node_modules/`, `playwright-report/`, `test-results/`.

---

## 1. Что можно безопасно удалять (артефакты)

Эти каталоги пересоздаются при сборке/тестах и уже указаны в [.gitignore](e:\VScode\cattle-tracker.gitignore):


| Что                    | Действие                                                 |
| ---------------------- | -------------------------------------------------------- |
| **playwright-report/** | Удалять при желании. Создаётся заново при `npm run e2e`. |
| **test-results/**      | Аналогично — артефакты Playwright, можно удалять.        |


Команда для быстрой очистки (по желанию):  
`Remove-Item -Recurse -Force playwright-report, test-results -ErrorAction SilentlyContinue`

---

## 2. Папка `dist/` в корне

- **dist/** — результат `npm run build` (Vite). Сейчас она **отслеживается в git** (есть изменения в `dist/app.js`, `dist/index.html`).
- Обычно артефакты сборки не коммитят. Рекомендация: добавить в корневой [.gitignore](e:\VScode\cattle-tracker.gitignore) строку `dist/` (рядом уже есть `electron/dist/`), затем перестать коммитить содержимое `dist/`. Локально папку можно в любой момент удалять — она пересоздаётся командой `npm run build` (и при `npm run installer`).

## 3. Критично: секрет Google в корне

В корне лежит файл  
`client_secret_64515659927-bb590b6kmp1f4j9lbsnpkhd4jib0teae.apps.googleusercontent.com.json`  
с **client_secret** Google OAuth. Такой файл не должен находиться в репозитории.

Рекомендуемые шаги:

1. Добавить в [.gitignore](e:\VScode\cattle-tracker.gitignore) правило, например:
  `client_secret*.json` или полное имя файла.
2. Убрать файл из индекса Git (не удаляя с диска, если он нужен локально):
  `git rm --cached "client_secret_64515659927-bb590b6kmp1f4j9lbsnpkhd4jib0teae.apps.googleusercontent.com.json"`.
3. Хранить секрет вне репо: например в `server/.env` или в переменных окружения, а в коде читать оттуда (если этот секрет используется в приложении/сервере).
4. В Google Cloud Console при необходимости перевыпустить OAuth-ключ, так как он мог попасть в историю репозитория.

В коде по проекту ссылок на этот файл по имени не найдено — добавление в `.gitignore` и `git rm --cached` достаточны, чтобы он больше не коммитился.

## 4. Дублирование скриптов запуска сервера

В корне два скрипта, запускающих сервер:

- [start-server.bat](e:\VScode\cattle-tracker\start-server.bat) — проверяет наличие Node, при необходимости делает `npm install` в `server/`, затем `node server.js`.
- [Запустить-сервер.cmd](e:\VScode\cattle-tracker\Запустить-сервер.cmd) — только переходит в `server` и запускает `node server.js`.

По сути дублируют одну задачу. Варианты:

- **Вариант А:** Оставить один скрипт (например `Запустить-сервер.cmd`), доработать его логикой из `start-server.bat` (проверка Node, установка зависимостей при необходимости), второй удалить.
- **Вариант Б:** Оставить оба, явно указав в README или в комментарии в файлах разницу (например «полная версия с установкой зависимостей» и «быстрый запуск»).

Удаление одного из файлов — по желанию, не обязательно.

## 5. Папка `.cursor/plans`

В [.cursor/plans](e:\VScode\cattle-tracker.cursor\plans) много файлов планов (около 25 уникальных названий). Это не «мусор», а рабочая история планов Cursor.

Варианты без потери полезного:

- Создать внутри `.cursor/plans` подпапку `archive/` и перенести туда планы, которые уже выполнены или не актуальны — в корне планов останется меньше.
- Или оставить как есть — на работу проекта это не влияет.

Удалять всё подряд не стоит, если планы ещё используются.

## 6. Документация и прочие файлы в корне

В корне есть:

- README.md, MULTIPLATFORM.md, RELEASE_CHECKLIST.md;
- файлы с русскими именами (Инструкция, Деплой_сервера_и_приложения, Установка_и_запуск и т.д.);
- несколько `.cmd` для сборки/запуска (Собрать-установщик, Собрать-APK, Запустить-сервер и др.).

Удалять их не нужно — это документация и точки входа. При желании можно **уменьшить количество файлов в корне**, перенеся часть документации в каталог `docs/` (например MULTIPLATFORM.md, RELEASE_CHECKLIST.md, Инструкция, Деплой, Установка), оставив в корне только README.md. Ссылки в README при этом обновить. Это опционально и только для порядка.

## 7. Что не трогать

- **lib/** — в ней только [lib/README.txt](e:\VScode\cattle-tracker\lib\README.txt) с инструкцией положить `xlsx.full.min.js`. Папка нужна для экспорта/импорта Excel, удалять или очищать не стоит.
- **index.html**, **sw.js**, **manifest.json** в корне — исходники, используемые Vite и приложением; не удалять.
- **start.bat**, **update.bat** — полезные скрипты (запуск Electron и быстрый git add/commit/push); по желанию оставить.

## Краткий чек-лист


| Действие                                                                                    | Приоритет                               | Риск                         |
| ------------------------------------------------------------------------------------------- | --------------------------------------- | ---------------------------- |
| Удалить локально `playwright-report/`, `test-results/` при желании                          | Низкий                                  | Нет                          |
| Добавить в `.gitignore`: `dist/` и `client_secret*.json`                                    | Высокий (безопасность и порядок в репо) | Нет                          |
| Убрать `client_secret_*.json` из индекса Git (`git rm --cached ...`)                        | Высокий                                 | Нет (файл остаётся на диске) |
| Объединить или пометить дубликаты запуска сервера (start-server.bat / Запустить-сервер.cmd) | По желанию                              | Нет                          |
| Архивировать старые планы в `.cursor/plans/archive/`                                        | По желанию                              | Нет                          |
| Перенести часть .md в `docs/`                                                               | По желанию                              | Обновить ссылки в README     |


После изменений в `.gitignore` и `git rm --cached` для секрета имеет смысл один раз пересобрать установщик и проверить, что приложение и сервер работают как раньше.
