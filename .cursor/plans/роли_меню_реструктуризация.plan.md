# План: роли (не админ), меню и реструктуризация разделов

**Аудит кода (актуально для репозитория):** запланированные переносы Excel / протоколов / списков в настройках хозяйства **в исходниках пока не реализованы**. Ниже — зафиксированное состояние файлов и оставшаяся работа.

## Текущее состояние (факты по коду)

### Меню и подменю

- Конфиг [`js/core/menu.js`](e:/VScode/cattle-tracker/js/core/menu.js) (зеркало [`electron/js/core/menu.js`](e:/VScode/cattle-tracker/electron/js/core/menu.js)):
  - В группе **`data`** по-прежнему три пункта Excel: экспорт, шаблон, импорт (строки с `exportToExcel`, `downloadTemplate`, `#importFile`).
  - В группе **`settings`** есть отдельная кнопка **«Протоколы синхронизации»** → `navigate('protocols')`.
- `renderSubmenu()` строит кнопки из `MENU_GROUPS` **без** фильтрации по `role`.
- `navigate()` / `syncRouteToScreen()` **не** блокируют экраны для `viewer` (обход через hash возможен).

### Администрирование и импорт

- [`index.html`](e:/VScode/cattle-tracker/index.html) `#admin-screen`: секции **«Пользователи»** и **«Отчёты пользователей»**; секции Excel нет.
- Скрытый `#importFile` по-прежнему внутри **`#menu-screen`** (не в админке).
- Кнопка группы **«Администрирование»** показывается только при `role === 'admin'` и `CATTLE_TRACKER_USE_API` — логика в [`js/core/users.js`](e:/VScode/cattle-tracker/js/core/users.js) (`updateAuthBar`).

### Настройки хозяйства

- [`index.html`](e:/VScode/cattle-tracker/index.html) `#farm-settings-screen`: три **`textarea`** (`farmSettingsTechnicians`, `farmSettingsBulls`, `farmSettingsDrugs`), общая кнопка **«Сохранить»**; секция **«Код осеменения»** — только подсказка, без полей.
- Логика в [`js/features/farm-settings.js`](e:/VScode/cattle-tracker/js/features/farm-settings.js): построчный разбор, `localStorage`, `refreshFarmDatalists()` — без разграничения по роли.

### Роли на клиенте

- Роли регистрации: `admin`, `operator`, `viewer` (форма в `index.html`, `regRole`).
- В [`js/core/users.js`](e:/VScode/cattle-tracker/js/core/users.js) объявлены `canAdd` / `canEdit` / `canDelete` (для `viewer` — false), они выставлены на `window`, но **в остальном `js/` почти не используются** (кроме локальной переменной в `admin.js` для строки пользователя — не то же самое).
- Локальная функция **`isAdmin()`** есть только в [`js/features/sync/sync-desktop-apk-admin.js`](e:/VScode/cattle-tracker/js/features/sync/sync-desktop-apk-admin.js) (блок APK на экране синхронизации), не как общий хелпер для меню.

### Сервер (контекст)

- Чтение записей и списка протоколов: `GET` с `requireAuth` ([`server/routes/entries.js`](e:/VScode/cattle-tracker/server/routes/entries.js), [`server/routes/protocols.js`](e:/VScode/cattle-tracker/server/routes/protocols.js)).
- Создание/изменение/удаление записей и протоколов: `requireRole('admin', 'operator')`.
- Импорт объекта: `POST /api/objects/import` — сейчас `admin` и `operator` ([`server/routes/objects.js`](e:/VScode/cattle-tracker/server/routes/objects.js)).

## Целевая модель (требования)

1. **Не администратор** — различать как минимум:
   - **`operator`**: полевые действия; без админ-панели пользователей; без Excel-массовых операций в UI (после переноса в админку).
   - **`viewer`**: только просмотр; скрыть «Действия», добавление/редактирование/удаление в UI, переключатель объектов (добавить/изменить/удалить); защита от прямого перехода по hash.

2. **Excel**: экспорт, импорт, шаблон — только в разделе **«Администрирование»** (не в «Работа с данными»). При необходимости жёстко ограничить **сервер** только `admin` для массового импорта.

3. **Протоколы синхронизации**: убрать пункт из подменю **«Настройки»**; вход — с экрана **«Настройки хозяйства»** (кнопка → тот же `protocols-screen`). Обновить тексты подсказок и кнопку «Назад» на `#protocols-screen` для логичной навигации.

4. **Настройки хозяйства**: вместо больших `textarea` — компактный UI: список значений + одно поле ввода и «Добавить»; **редактирование справочников и сохранение — только `admin`**; остальным — только просмотр (или скрыть секции — на усмотрение, в плане заложено read-only списки).

## Порядок реализации

1. **Общие хелперы роли** (например `window.isFarmSettingsAdmin` / `isAppAdmin` или проверка `getCurrentUser().role === 'admin'`) в одном месте, переиспользование из меню, farm-settings, protocols UI.

2. **Меню и навигация**
   - Удалить из `MENU_GROUPS.data` три Excel-кнопки; добавить секцию Excel на `#admin-screen` + перенос/дублирование `#importFile` так, чтобы импорт работал с экрана админки.
   - Удалить из `MENU_GROUPS.settings` кнопку протоколов; на `#farm-settings-screen` добавить кнопку перехода к `protocols`.
   - В `renderSubmenu()` (и при необходимости на главном меню) фильтровать кнопки для `viewer` (и скрыть целиком секцию «Действия» на `#menu-screen`).
   - В `navigate()` + `syncRouteToScreen()` — редирект с toast для запрещённых экранов у `viewer`.

3. **Права в интерфейсе данных**
   - Подключить `canAdd` / `canEdit` / `canDelete` в формах списка, карточки коровы, переключателе объектов (см. [`js/core/menu.js`](e:/VScode/cattle-tracker/js/core/menu.js) `updateObjectSwitcher`, соответствующие feature-модули).

4. **Farm-settings и протоколы**
   - Заменить `textarea` на списки + input; в `initFarmSettingsScreen` вешать обработчики сохранения/добавления/удаления только для `admin`.
   - В [`js/features/protocols.js`](e:/VScode/cattle-tracker/js/features/protocols.js) (или где рендерится форма): для `viewer` — скрыть кнопки добавления/удаления/сохранения (чтение списка разрешено и на сервере).

5. **Копии под Electron** — те же правки в `electron/index.html`, `electron/js/...`.

6. **Дополнительно:** обновить блок подсказок первого запуска (`firstRunHints`), e2e при необходимости ([`e2e/smoke-electron.spec.js`](e:/VScode/cattle-tracker/e2e/smoke-electron.spec.js) — переход на protocols).

7. **Версия:** после внесения кода — patch в корневом `package.json` по правилам проекта.
