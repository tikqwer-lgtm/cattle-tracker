# Формат резервной копии (ZIP)

Версия формата: **1** (`manifest.format`: `cattle-tracker-backup`).

## Имя файла

`cattle-tracker-{название_базы}-{дата}.zip`

## Структура архива

| Файл | Содержимое | При восстановлении |
|------|------------|-------------------|
| `manifest.json` | `format`, `version`, `objectId`, `objectName`, `createdAt`, `appVersion` | Справочно |
| `farm-card.json` | Карточка хозяйства (контакты, адреса, показатели, события) | Применяется, если файл есть |
| `farm-settings.json` | `technicians`, `bulls`, `drugs`, `protocols` | Применяется, если файл есть |
| `herd/entries.json` | Массив карточек коров | **Источник правды** для стада |
| `herd/stall-layout.json` | Схема стойломест | Применяется, если файл есть |
| `herd/inseminations.json` | Плоский список осеменений | Не восстанавливается (только отчёт) |
| `herd/events.json` | Плоский список событий | Не восстанавливается (только отчёт) |

Отсутствующие файлы при восстановлении **не изменяют** соответствующий слой.

В приложении при восстановлении ZIP показывается диалог: можно восстановить только **стадо**, только **настройки**, только **карточку** или любую комбинацию.

## Legacy JSON

Одиночный `.json` с полем `entries` (и опционально `stall_layout`, `protocols`) трактуется как резерв **только стада** (+ доступные поля настроек, если указаны).

## API экспорта сервера

`GET /api/objects/:id/export` возвращает JSON: `entries`, `protocols`, `stall_layout`, `profile`, `farm_settings`, `farm_card`.
